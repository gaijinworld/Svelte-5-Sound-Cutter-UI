# Phase 1.1 — Precise MP3 Cut Mode

## Goal
Keep fast/lossless splitting as the default while offering a clearly labeled re-encode mode for users who prioritize tighter requested cut boundaries.

## Implemented in this phase
- `SplitMode = 'lossless' | 'precise'` and optional `SplitOptions` on `MediaSplitEngine.split()`.
- Browser engine command selection by split mode.
- UI radio selection for Fast/Lossless vs Precise.
- Mode-specific accuracy/quality explanation in the export panel.

## Modes
### Fast / Lossless — default
```text
-c:a copy
```
- No MP3 re-encoding.
- Preserves the source audio stream characteristics.
- Much faster and lower CPU cost.
- Cut points may align to nearby MP3 frame boundaries.

### Precise
```text
-c:a libmp3lame -q:a 2
```
- Decodes/re-encodes the selected audio.
- Intended for tighter requested boundaries.
- Slower and can change bitrate/encoding characteristics.

## Acceptance criteria
- Lossless remains the default.
- Mode cannot be changed while splitting is active.
- The selected mode is used consistently for all segments in the current batch.
- The UI explicitly warns that precise mode re-encodes.
- Both modes preserve the same segment selection and filename behavior.

## Verification before merge

Manual QA should export the same short segment in both modes, compare actual start/end behavior, inspect output with FFprobe, and verify the tradeoff is accurately represented in the UI.
